== Limits on values

[cols="1,2,2"]
|===
|Value |Rule |Why
|VM name |`[A-Za-z0-9][A-Za-z0-9-]{0,39}`, case-sensitive |40 characters leaves room for the VM's sockets under the 108-byte `sun_path`; the name appears in unit names, paths and the persistence id
|Persistence id |may contain uppercase |follows from case-sensitive VM names
|Share path |UTF-8, no control characters |shares are written into the guest's tab-separated `mounts` table
|Shares per VM |at most 24 |each share is a virtio-fs PCI device; the slot count bounds it
|Identifiers |ULID (incarnation, operation) |operator preference over UUIDv7; sortable by creation time
|===

== VM operations

=== Status

Status is collected tell-only: Root asks every twin and gathers answers for 5 s. A twin that has not answered by then shows as `Unknown`; a late answer is dropped. A quarantined VM has no twin and shows as `Quarantined { reason }` (a `VmCondition` variant), taken from its `quarantine/<name>` stream.

=== Stop

* `Stop` on a `Starting` VM cancels the start; the operation that started it ends with `vm.stopped_while_starting`.
* `Stop` on a `Failed` VM takes down the leftovers its failed start recorded.
* LocalQemu stops a machine in three steps: QMP `system_powerdown`, then `SIGTERM` after 30 s, then `SIGKILL` after 10 s more. Each signal goes only to a process whose identity is verified.

=== Start

* The boot timeout is fixed at 120 s.
* The Builder runs before GuestVm (0002); a `nix build` still running when the runtime stops is left to finish. It is idempotent, and the next start uses its result.
* The guest `term` file is always removed: no terminal is attached to a VM (0002, console).

=== Quarantine

0002's quarantine is implemented as follows:

* A twin that becomes `Unrecoverable` reports `VmReport::Unrecoverable { reason }` to Root. Root marks the VM quarantined in memory at once; the twin stays alive refusing commands, and Root routes nothing to it from then on.
* Root is not a persistent actor. It replays `quarantine/<name>` first: a live event means the VM is already recorded. Otherwise it appends `Quarantined { reason }` after the stream's last position (position 1 unless an earlier record was retired by `vacuum_vm`) through a plain `JournalMessage::Persist`; the journal's answers reach it as `RootMessage::Journal`. Root is the only writer, so a conflict means already recorded and is not an error. A store failure leaves the quarantine in memory only, logged.
* At start Root lists `quarantine/*` and `vm/*`, and replays every listed quarantine stream for its reason. Requests are held until both listings and every reason are in; then a twin is spawned for every `vm/*` name that is not quarantined. A record that can't be read counts as quarantined: its twin would otherwise replay a stream that may be broken.
* `start` and `stop` on a quarantined VM are refused (`runtime.vm.quarantined`, hint: `amoeboid vacuum_vm NAME`); `status` shows `Quarantined { reason }` without asking any twin.
* Envelope: `{"version": 1, "event": {"quarantined": {"reason": Report}}}`, the persistent actors' envelope.

=== Vacuum

`amoeboid vacuum_vm NAME` removes everything a VM owns: it stops the VM (reaping its verified processes), removes its runtime directory and state directory, and retires its streams (`vm/<name>`, `quarantine/<name>`). It works on quarantined VMs, which have no twin to stop them.

A stream is retired by a **tombstone**, not deleted: the journal records that the stream ended, and a retired stream is neither replayed nor listed in the registry. The history stays in the journal.

=== Tombstones

[source,sql]
----
CREATE TABLE tombstones (
  persistence_id TEXT PRIMARY KEY,
  through        INTEGER NOT NULL,   -- events at or below are retired
  at             INTEGER NOT NULL
) STRICT;                            -- journal schema version 2; version 1 migrates in place
----

* `JournalMessage::Retire { id }` sets `through` to the stream's last position (answered `Retired` or `RetireFailed`). Retiring an empty or already retired stream changes nothing.
* A replay returns `Replay { events, last }`: the events above `through`, and the stream's last position with retired events included. A persistent actor appends after `last`, as an Akka persistent actor continues after its highest sequence number once its messages are deleted.
* A stream is listed only while it has an event above its tombstone.
* A name is reused by continuing its stream: a new twin for a vacuumed name replays nothing, so it is a fresh VM (`Created` with a new incarnation), and its events follow the tombstone. The writer fence is unchanged: an append must start at `last + 1`.

== Supervision

`ractor-supervisor` is a dependency with `default-features = false`: its default features turn on ractor's `async-trait` feature, which breaks actors written with native `async fn`. Root's twins go under a `DynamicSupervisor`. A twin's child (Builder, GuestVm, Hypervisor) that ends is respawned under a supervisor strategy rather than only reported as `ChildEnded`. The strategy and intensity per level stay open (0002).

== Runtime placement

=== The runtime's own files

`daemon.lock` and `journal.sqlite` move to `$XDG_STATE_HOME/amoeboid`, apart from VM data in `$XDG_DATA_HOME/amoeboid`. This answers 0002's open question. The move is not implemented yet; until then both stay in `$XDG_DATA_HOME/amoeboid`, marked by a TODO in `runtime/paths.rs`.

=== systemd units

`amoeboid daemon install` writes `~/.config/systemd/user/amoeboid.socket` and `amoeboid.service` and enables the socket:

[cols="1,2"]
|===
|Setting |Reason
|`ListenStream=%t/amoeboid/runtime.sock`, `SocketMode=0600`, `DirectoryMode=0700` |same-user socket (0002, protocol)
|`Restart=on-failure` |a dead runtime comes back and adopts its VMs
|`KillMode=process` |VM processes already run in their own scopes; this spares them a second time
|`Environment="PATH=…"` captured at install |the user manager's `PATH` is often minimal; the runtime needs `nix`, `ssh-keygen` and `systemd-run`
|`ExecStart=` the `amoeboid-daemon` next to the `amoeboid` binary that ran `install` |the CLI and the runtime ship together and must match in protocol version
|===

== How we work (operator preferences)

* Work is driven manually and closely steered. No implementation subagents; research outside the repo goes to a Sonnet 5.5 subagent at low effort, so the main context stays for design and review.
* Types first, for review, before bodies, whenever a unit introduces design. Then one commit per significant unit, each gated: `cargo test --workspace`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo fmt --all --check` must all pass *before* `git commit` (chain with `&&`; an earlier commit once slipped through with a failing test because grep masked the exit code). Loop the tests 5+ times for flakes before committing anything touching processes or timing.
* After each significant unit: an explainer for review: compact, technical, tables and ASCII diagrams, no filler prose. Code comments compact and technical too.
* Never deviate from the design silently: stop and ask. Record decisions in the decision records (0002 has been amended many times), not only in chat.
* No abbreviations anywhere (identifiers, wire fields, SQL columns, docs): `OperationId`, `Sequence`, `message`, `error`, `user_id`. Only external APIs keep theirs (ractor's `type Msg`).
* Explain in Akka / Erlang-OTP terms (EventSourcedBehavior, command/event handlers, supervisors), never borrowed pattern names from other ecosystems. Scala analogies are welcome in chat, never in repo files.
* "Make impossible states unrepresentable" rather than typing impossible errors; no unchecked constructors; refinement by plain newtypes with private fields and validating `parse`; no `unsafe`, no `unwrap`/`expect`/`panic` outside tests (tests may `unwrap`, not `panic!`).
* Polymorphism through enums and pattern matching ("enum maxxing"); test doubles as enum variants (`BuildCommand::Scripted`, `Placement::Direct`) or as actors speaking the same message enum.
* Commit messages: imperative subject, technical body, end with the Co-Authored-By line given by the session.

== Architecture in one screen

----
amoeboid-daemon (systemd socket-activated) ── Runtime::start
  daemon.lock (flock) ─ socket ─ Root
Root (plain actor): Journal (linked, essential), Listener (linked, essential) ─ Session per client
     registry = journal streams under `vm` (listed at start, twins spawned eagerly)
     waiters: OperationId → session (in memory)    statuses: status collections (5 s timeout)
     holds requests until the stream listing arrived
VmTwin (Persistent<VmTwin>, stream vm/<name>, the VM's digital twin; only persistent actor of a VM)
  ├─ Builder     host.nix, VM's Nix config (bundled / existing / rebase), nix build → build.log
  ├─ GuestVm     host key, guest files, config copies (seeding decided by twin), port, sshd wait
  └─ LocalQemu   (Hypervisor backend, reached as DerivedActorRef<HypervisorCommand>)
       virtiofsd × shares + qemu, each in scope amoeboid-<vm>-<role> under amoeboid.slice

CLI `amoeboid`: ping, start, stop, status, daemon install
----

== Discussed and decided along the way (check these are reflected in 0002)

These were settled in conversation; most were written into 0002, but if 0002 is silent on one, this list is the record.

* Effects as data; components swapped by swapping the actor that handles a message enum; backend internals private to their actor; commands at the right altitude (`Boot{plan}`, never argv).
* Tell-only messaging between actors. Awaiting I/O inside a handler (SQLite, sockets, QMP) is allowed; awaiting another actor is not. Replies carry correlation ids; cross-type replies via `DerivedActorRef` with exactly one wrapper variant per derived type (ractor's `get_derived` panics if the conversion back fails).
* Journal is its own actor (option A of the journal discussion), single SQLite connection (tokio-rusqlite). Persistent actors stash commands while persisting; the generic persistent actor's handler is synchronous (kill lands between steps).
* Akka-style persistence, one stream per persistent actor, but within a VM subtree only the twin persists (option B, "twin owns everything"); children report observations and are spawned with what to adopt.
* Commands vs observations: observations are never stashed while reconciling (reconcile runs on them); dropped while `Recovering` (they come from a previous incarnation; `on_recovered` re-probes); held in order while `Persisting`.
* Generic `Reconciling` mode with `reconciled(state)`; currently the twin returns `true` (adoption answers run in `Ready`).
* Unrecoverable replay (undecodable event, unknown event version) quarantines instead of crashing; replay store errors restart with backoff; persist conflict/timeout stop the actor (supervisor restarts, replay rebuilds).
* Actor reset is a guarantee; generations on every message; writer appends only at its own stream position; parents accept child reports only if strictly newer (omicron's `state_generation < new` rule).
* VMs outlive the runtime: one transient scope per process (`systemd-run --user --scope --collect --slice=amoeboid.slice --unit=amoeboid-<vm>-<role>`; a scope holds one spawn, and the fixed unit name makes a duplicate spawn fail at systemd-run), own process group, CLOEXEC everywhere, pidfd adoption.
* Process identity = process id + start time (ticks since boot) + boot id; the executable is not part of it (the runner script execs qemu).
* Deterministic nonce `Nonce::of(vm, incarnation, generation, role)` in `AMOEBOID_NONCE`; incarnation is a ULID minted by Root and persisted in the twin's first event `Created{incarnation, backend}`; nonce search takes the topmost carrier (children inherit the environment).
* Typed roles per backend: `ProcessRole::Local(LocalRole::{Qemu, Virtiofsd(SharedDirectory)})`; the twin decides on machine-level observations (`MachineRunning`, `MachineStopped{reason}`); coupling between processes is the backend's knowledge.
* Hosting enum: `SystemdUser{ActivatedSocket}` (via listenfd, no unsafe) | `InProcess`; no foreground mode anywhere (daemon or console); CLI is client only.
* Protocol: per-direction, per-domain enums; `HandshakeStart`/`HandshakeAccepted`/`HandshakeRejected`; exact protocol version match; 4-byte big-endian length prefix, JSON, 1 MiB; client-minted ULID operation ids; transport replaceable (HTTP mapping noted; gRPC only for a future remote hypervisor link).
* Identifiers are ULIDs (operator preference over UUIDv7).
* Diagnostic trait (code, message, hint) on every operator-facing error, with a catalogue test; errors cross the socket as `Report`.
* Lints dropped: `arithmetic_side_effects`, `indexing_slicing`, `as_conversions` (refined types guard what matters).
* Framework: ractor + ractor-supervisor; kameo considered (no escalation on restart limit, no timers found), tellus considered (Akka-like with persistence but two months old and Postgres only).
* Rust chosen deliberately (Linux plumbing and Lance/Parquet native; the operator wants to get good at it); the harness that will consume this library is a separate project (rig, TEA reducers over event streams). The control plane is a library; the daemon is one host of it.
* Registry: journal stream names (`vm/*`) are the registry; Root is not a persistent actor; quarantine as `quarantine/<name>` streams (decided A over a separate table).
* VM names: `[A-Za-z0-9][A-Za-z0-9-]{0,39}` (40, leaving room under `sun_path`); persistence ids allow uppercase (names are case-sensitive).
* Share paths must be UTF-8 without control characters (they go into the guest's tab-separated `mounts` table); at most 24 shares (PCI slots).
* Status aggregation is tell-only with a 5 s timeout; unanswered VMs show as `Unknown`.
* `Stop` on a starting VM cancels the start; `Stop` on a failed start takes down its leftovers.

== Lessons and gotchas

* Fork vs lock race in tests: a fork in a parallel test holds copies of every fd until its child execs (O_CLOEXEC acts at exec), keeping a dropped flock alive. `testing::forks()` is a mutex taken by `process::spawn` around the fork (test builds only) and by tests that hold lock fds for their whole run. `testing::executable` writes test scripts under it too (avoids ETXTBSY).
* Don't assert a racy fact in a test (a "free" port staying free).
* Exit notifications between processes arrive in any order (a virtiofsd exits when its qemu goes away); decisions must check the world (liveness) rather than trust arrival order.
* `AsyncFd::register` is unsafe; adopted processes are watched by a blocking `poll` on the pidfd with a 1 s timeout and a cancel flag, so runtime shutdown is not held by a running VM.
* `systemd-socket-activate` (used for manual runs) runs the daemon once and exits with it; after killing the daemon, start the activator again. A real `amoeboid.socket` unit re-activates by itself.
* zsh does not word-split `$VAR` in commands; spell out long argv in manual tests.
* Scripted Python-style string surgery on Rust files went wrong twice (code landing inside an impl block, a dropped `match` line); prefer precise edits and rebuild immediately.

== Real-VM check (repeatable)

Uses scratch data so nothing touches the real data directory or the Python VM:

----
S=<scratch dir>; mkdir -p $S/data $S/project; mkdir -m 700 -p $XDG_RUNTIME_DIR/amoeboid
export XDG_DATA_HOME=$S/data
systemd-socket-activate -l $XDG_RUNTIME_DIR/amoeboid/runtime.sock \
  -E XDG_DATA_HOME -E XDG_RUNTIME_DIR -E HOME -E USER -E PATH -E AMOEBOID_LOG=info \
  ./target/debug/amoeboid-daemon >> $S/daemon.log 2>&1 &
./target/debug/amoeboid start --name scratch $S/project      # prints the ssh command
./target/debug/amoeboid status
pkill -KILL -x amoeboid-daemon   # VM keeps running; restart the activator, status shows it running
./target/debug/amoeboid stop --name scratch                   # ~2 s via ACPI powerdown
sqlite3 $S/data/amoeboid/journal.sqlite "select sequence, payload from events where persistence_id='vm/scratch'"
# clean up: systemctl --user stop 'amoeboid-scratch-*.scope'; kill daemon and activator;
#           rm -rf $XDG_RUNTIME_DIR/amoeboid $S
----

Results last run: start 16 s with a cached build; guest hostname, no failed units, 7 virtiofs mounts, host↔guest file ownership mapped to the host user; VM survived SIGKILL of the daemon; new runtime adopted it with no request; graceful stop 1.7–1.8 s; generation 2 restart without re-seeding.
